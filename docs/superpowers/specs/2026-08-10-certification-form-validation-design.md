# Валидация анкеты сертификации

## Цель

Устранить ложную ошибку «ответьте на все обязательные вопросы», когда пользователь вводит понятное человеку числовое значение с разделителями или диапазоном. Сделать каждую ошибку локальной и понятной, не заставляя пользователя повторно просматривать все 45 вопросов.

## Правила числовых ответов

Числовые поля перестают использовать HTML `input type="number"` и становятся текстовыми полями. Для полей с одним числом включается цифровая клавиатура (`inputMode="numeric"`), а для диапазонов остаётся обычная клавиатура, чтобы на телефоне было доступно тире. Это позволяет приложению самостоятельно проверить введённую строку и показать конкретную причину ошибки, не теряя значение из-за браузерной очистки.

Поля возраста и дохода принимают одно неотрицательное целое число. Разрешены визуальные разделители тысяч: пробелы, неразрывные пробелы и запятые. Примеры допустимого ввода: `1300`, `1 300`, `1,300`. Диапазоны в этих полях отклоняются с подсказкой «Укажите одно число».

Поля стоимости часа, количества учеников и часов принимают одно число либо диапазон из двух чисел. Разрешены дефис и короткое/длинное тире: `1000-1300`, `1000–1300`, `1000—1300`. Каждая граница диапазона также может содержать разделители тысяч. Левая граница не должна превышать правую.

Отрицательные значения, буквы, дробные значения, несколько диапазонов и строки без цифр считаются ошибкой. Ноль допустим: у участника до обучения могли отсутствовать доход или ученики.

## Лимиты

- Числовой ответ: не более 40 введённых символов.
- Короткий текстовый ответ: не более 200 символов.
- Развёрнутый ответ: не более 4000 символов.

Лимиты проверяются приложением, а не молча обрезают значение. Под полем показывается счётчик символов при приближении к лимиту и явная ошибка после превышения.

## Поведение интерфейса

Под каждым числовым полем постоянно отображается короткая подсказка с допустимым форматом и примером. Ошибка появляется после ухода из поля; после этого обновляется сразу при исправлении значения.

При нажатии «Перейти к тестированию» приложение:

1. Проверяет обязательность, формат и лимит каждого ответа.
2. Подсвечивает все проблемные поля и связывает сообщения через `aria-invalid` и `aria-describedby`.
3. Прокручивает страницу к первому проблемному вопросу и переводит фокус в его поле.
4. Показывает общий тост с количеством полей, которые нужно исправить, вместо сообщения только о незаполненных вопросах.

Для обычных текстовых вопросов обязательное значение из одних пробелов остаётся пустым. Для чекбоксов и радиокнопок сохраняется существующее правило: должен быть выбран хотя бы один вариант.

## Архитектура

Чистые функции разбора и проверки размещаются в отдельном модуле `lib/certification-form-validation.ts`. Модуль не зависит от React и возвращает структурированный результат: нормализованные числовые части либо локализованное сообщение об ошибке.

Компонент анкеты хранит исходный пользовательский текст, чтобы не менять его неожиданно. Он добавляет метаданные правил к девяти числовым вопросам, состояние посещённых полей и флаг попытки продолжить. Отправляемый JSON сохраняет исходные ответы; изменение формата хранения и миграция базы не требуются.

## Обработка ошибок

Приоритет сообщений для поля: превышение лимита, обязательность, затем формат. Примеры сообщений:

- «Это обязательный вопрос».
- «Укажите одно целое число, например 20000».
- «Можно указать одно число или диапазон, например 1000–1300».
- «Начало диапазона не может быть больше конца».
- «Слишком длинный ответ: максимум 40 символов».

## Тестирование

Unit-тесты покрывают обычные числа, пробелы и запятые, три вида тире, диапазоны с разделителями, ноль, отрицательные и дробные значения, буквы, обратный диапазон и все лимиты. Отдельно проверяется агрегирование ошибок обязательных полей.

После unit-тестов выполняются TypeScript-проверка и браузерный сценарий: некорректный диапазон показывает локальную ошибку, допустимый `1000–1300` сохраняется и не блокирует переход, а превышение лимита показывает счётчик и сообщение.

## Вне текущего изменения

Автосохранение черновика анкеты полезно для длинной формы, но не требуется для устранения текущего сбоя и будет отдельной задачей.
